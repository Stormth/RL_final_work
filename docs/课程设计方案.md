# 执行反馈驱动的代码修复强化学习：课程设计方案 v2

> 定位：强化学习课程设计 · 3 人 · 5 周（+1 周缓冲）
> 算力：单卡 40–80GB（A6000 / A100 / H100）· LoRA 微调
> 形态：训练 Qwen2.5-Coder-7B，**工具链作为 RL 环境**
> 版本说明：v2 取代 v1。v1 的"编排层 RL"方案保留在[附录 A](#附录-a编排层-rl方案v1保留作对照)，作为降级预案与对照基线。

---

## 0. 一句话概括

用**隐藏测试作为可验证奖励**，对 7B 代码模型做多奖励强化学习：先"一次生成"，失败后把执行反馈回灌，让模型"修复一轮"；以 GRPO 打底，用 **GDPO 解耦多奖励归一化**，解决"做对"与"省一轮/不超时"之间的奖励尺度冲突。在**较新题目 + 扰动测试**上评测（数据集的时限局限见 §4）。

## 0.1 v1 → v2 变更摘要

| | v1（已废弃） | v2（当前） |
|---|---|---|
| 训练对象 | 不训练模型 | LoRA 训练 Qwen2.5-Coder-7B |
| RL 算法 | 表格 Q-learning / LinUCB | GRPO / **GDPO** |
| 学习对象 | 7 个工具动作的编排策略 | 模型参数（token 级策略） |
| 工具链的角色 | 被调度的工具 | **RL 环境**（沙箱 + 判定 + 反馈构造） |
| 主指标 | AC@8、成本-成功率 Pareto | pass@1、修复增益、平均轮数与耗时 |
| 风险 | 低 | 中高，靠 4 个 gate 兜底 |

**为什么放弃 v1**：v1 的立论是"7B 做 policy gradient 不现实"，而单卡 40–80GB + LoRA 已经推翻了这个前提。继续做编排层 RL 反而会把最有价值的部分（可验证奖励、执行反馈）浪费掉。

## 1. 问题定义

| 项 | 定义 |
|---|---|
| 输入 | LeetCode 函数式题：题面 + `class Solution` 签名 + 2~3 个公开样例 |
| 轨迹 | `τ = (x, y₁, f, y₂)`：题面 → 首解 → 执行反馈 → 修复解 |
| 预算 | `T = 2` 轮模型调用（W4 可扩到 3 轮） |
| 判定 | 只在**隐藏测试**上判；公开样例进 prompt，隐藏测试绝不进上下文 |
| 目标 | `max E[1(最终 AC)] − λ₁·E[轮数代价] + λ₂·E[效率]` |

**与"多采样投票"的区别**：我们不是在测试时采 8 条然后选一条，而是**更新参数**，让模型自己学会"看到失败反馈之后怎么改"。这两件事的实验意义完全不同——前者是 inference scaling，后者是 policy improvement。

---

## 2. 为什么是"一次生成 + 一轮修复"

完整 8 步 Agent 的训练基建成本是两轮的 5 倍以上：多轮 rollout 需要训练框架支持 `agent loop`（verl 的 agent 训练、或 TRL 的多轮工具调用），还要处理跨轮信用分配、沙箱并发、超时重试。单卡 7B 时这些开销会把每个 step 推到不可接受。

而"一轮修复"已经能承载我们想验证的全部命题：

1. 模型能否**读懂**执行反馈（`WA / RE / TLE` + 首个失败用例）；
2. 模型能否**定向修改**而不是重写；
3. 多奖励下，"做对"与"省一轮"的权衡是否真实存在。

**扩展路径**：W4 若有余力，把 `T` 扩到 3（`生成 → 修复 → 再修复`），并在奖励里加"第几轮通过"。这是天然的多步版本，不需要改训练框架。

## 3. 方法

### 3.1 形式化

把整条轨迹当成一个动作，做**序列级策略优化**（不是 token 级 MDP）：

```
策略:  π_θ(y₁ | x) · π_θ(y₂ | x, y₁, f)
回报:  R(τ) = R_correct(τ) + λ₁·R_cost(τ) + λ₂·R_eff(τ)
```

**GRPO（标量奖励）**：同一题采 `G=8` 条轨迹，组内标准化得优势：

```
Â_i = (R_i − mean(R_1..G)) / std(R_1..G)
```

**GDPO（多奖励）**：先对每个维度分别做组内标准化，再加权聚合：

```
Â_i⁽ᵏ⁾ = (R_i⁽ᵏ⁾ − mean_k) / std_k          k ∈ {correct, cost, eff}
Â_i    = Σ_k w_k · Â_i⁽ᵏ⁾
```

**这就是全部差别**——同样是 PPO 式裁剪目标，只换优势的算法。也正因如此，`GRPO → GDPO` 的切换在代码上只是一行配置，对照实验非常干净。

**为什么必须解耦**：`R_correct` 是 0/1 的稀疏信号，`R_cost` 是稠密的连续惩罚。加权求和后组内标准差由 `R_cost` 主导，模型会优先学"少调一轮"，而不是"改对"——表现为 pass@1 不动、平均轮数下降，看起来"训练有效"实则退化。这个失败模式必须在报告中作为反例写出来。

### 3.2 奖励设计

| 维度 | 定义 | 取值范围 | 稀疏性 |
|---|---|---|---|
| `R_correct` | 最终代码通过全部隐藏测试 = 1 | {0, 1} | 稀疏 |
| `R_cost` | `−(实际轮数 − 1)`，即用一轮修复记 −1 | {0, −1} | 稠密 |
| `R_eff` | 最大规模用例 TLE = −1；通过 = 0 | {−1, 0} | 稀疏 |

初始权重 `w = (1.0, 0.2, 0.2)`，W4 做权重扫描。

**防奖励作弊**（必须写进报告）：

- 隐藏测试与公开样例**分布不同**：隐藏集里混入边界值、极端规模、负数/空输入；
- 训练时**不把隐藏测试内容**写进 prompt，只回灌"首个失败用例的输入/期望/实际"；
- 抽检 20 条高奖励轨迹人工过一遍，确认不是硬编码样例；
- 用**时间切分**的测试集，防止"模型背过题"被误读成"学会了修复"。

### 3.3 训练配置

| 项 | 80GB 配置 | 48GB 降级 |
|---|---|---|
| 模型 | `Qwen2.5-Coder-7B-Instruct` | 退 `Qwen2.5-Coder-3B` |
| 微调 | LoRA `r=32, α=64`，全线性层 | `r=16` |
| 框架 | **TRL `GRPOTrainer` + vLLM（colocate）** | 同 |
| 备选框架 | **verl + [NVlabs/verl-GDPO](https://github.com/NVlabs/GDPO)** | 同 |
| group size | 8 | 4 |
| prompt / completion | 2048 / 1024 | 1536 / 768 |
| batch | 1 × grad_accum 8 | 1 × 8 |
| LR | 1e-5 | 1e-5 |
| KL β | 0.001 | 0.001 |
| 温度 | 0.9（采样） / 0.7（评测） | 同 |

**显存粗算（7B，bf16，80GB 卡）**：权重 14GB + LoRA 与优化器 ~2GB + 激活（梯度检查点）~15GB + vLLM KV cache（8×1k token）~15GB ≈ **45–55GB**。48GB 卡必须降 group size 与序列长度，否则 OOM。

### 3.4 工具链 = 环境

v1 设计的工具链在 v2 里降级为**环境实现**，价值不减：

```
env/
├── sandbox.py   # 子进程 + 超时 + 内存上限，禁用网络
├── judge.py     # 逐 assert 执行，CE/RE/TLE/WA/AC 分类，提取首个失败用例
└── prompts.py   # turn-1 生成模板 / turn-2 修复模板 / 反馈格式
```

**反馈格式**（决定了模型能不能学会）：

```
[执行结果] WA
[失败用例] nums = [3,3], target = 6
[期望输出] [0, 1]
[实际输出] [1, 0]
[提示] 返回顺序需满足题意；若题意允许多解，请按题目说明排序。
```

反馈只给**一个**失败用例，不给全部——信息量刚好够定位，又不至于让模型把它当模板背下来。

## 4. 数据

**数据集**：[`newfacade/LeetCodeDataset`](https://huggingface.co/datasets/newfacade/LeetCodeDataset)（Apache-2.0，数千题，含时间戳与参考解）。关键字段：

| 字段 | 用途 |
|---|---|
| `problem_description` / `starter_code` | 题面与函数签名 |
| `entry_point` | 构造 `candidate` |
| `test` | 判定用；**逐 assert 执行**得到部分通过率与失败用例 |
| `input_output` | 公开样例来源 |
| `completion` | 参考解：清洗校验 + 效率基线 |
| `estimated_date` | 时间切分，防污染 |
| `difficulty` | 难度分层与训练集筛选 |

**清洗（不做则结论不可信）**：

1. **参考解自检**：`completion` 必须通过该题全部 assert，否则丢弃。
2. **多解题过滤**：题面含 "any order" / "any valid" 的剔除，或挂手写 checker（≤10 题）。
3. **断言可解析**：能按行拆出独立 assert 的才纳入，否则整题只给 AC/WA。
4. **人工抽检 10%**：确认没有"参考解与断言一起错"的样本。

**切分**：

- **训练集**：400 题，Easy/Medium，`estimated_date < 2024-01`。
- **测试集**：`estimated_date ≥ 2024-01` 的题。

> **一个必须先说清的事实**：LeetCodeDataset 的最新题目只到 **2024-07**，所以"发布时间晚于模型训练截止日期"这条**只能部分满足**。因此测试集必须叠加**扰动测试**——改写函数名、替换常量、打乱多解题的输出顺序后再判一次，把"背题"和"会做"分开。报告里要如实写这条局限，不要含糊过去。
- 每题 assert 前 2~3 条 → 公开样例，其余 → 隐藏测试。

**难度校准（关键，别省）**：RL 的梯度来自组内差异。先用 base 模型每题采 8 条估计通过率 `p`，**只保留 `0.1 < p < 0.7` 的题**。`p ≈ 0` 的组优势全 0 无梯度，`p ≈ 1` 的组浪费算力。这是把 400 题筛到有效训练集的必要步骤，等价于 DAPO 的 dynamic sampling，但更省。

## 5. 实验设计

### 5.1 基线（少一条都会被问）

| 基线 | 做法 | 作用 |
|---|---|---|
| B0 Base | 零样本，单轮 | 下界 |
| **B1 SFT** | 用参考解做 1 epoch SFT | **最危险的反例**：RL 打不过 SFT 就没意义 |
| B2 GRPO-scalar | 奖励加权求和，GRPO | 证明"解耦归一化"本身有用 |
| B3 Best-of-8 | 采样 8 条，测试用例选优 | 证明"不是靠采样次数堆出来的" |
| **P1 GRPO-2turn** | 两轮 + 标量奖励 | 证明"修复轮"有增益 |
| **P2 GDPO-2turn** | 两轮 + 三奖励解耦 | 主结果 |

### 5.2 指标

| 指标 | 定义 | 说明 |
|---|---|---|
| **pass@1** | 首解通过率 | 主指标，与 B0 对比 |
| **pass@1→2** | "修复一轮后通过 / 首解失败"的条件通过率 | **最能说明"模型学会了改"** |
| avg_turns | 平均消耗轮数 | 成本 |
| avg_tokens | 平均 token | 成本 |
| wall_clock | 每题端到端耗时 | 可用性 |
| **AC–cost Pareto** | 权重扫描得到的曲线 | 主图 |

### 5.3 消融

- 去掉 `R_cost` / 去掉 `R_eff` → 各维度的贡献
- `T=1` vs `T=2` vs `T=3` → 修复轮数收益递减点
- 奖励权重扫描 → Pareto 前沿
- LoRA rank（16 vs 32）→ 容量敏感性
- 难度分层（Easy / Medium）

### 5.4 统计

- 3 个训练 seed × 100 题；报告均值与 **bootstrap 95% CI**。
- 评测时固定温度与采样 seed，做**配对比较**（同一题跑各模型），方差显著下降。
- 只报"均值 + 星号"是答辩被问爆的位置，别省。

### 5.5 预期结论（先登记，防事后编故事）

1. SFT 在 Easy 上很强，但 Medium 上不如 GRPO——RL 的价值在"难例的定向修复"。
2. `R_cost` 单独使用会让 pass@1 下降、轮数下降；只有与 `R_correct` 解耦后才能兼得。
3. GDPO 相对 GRPO 的主要收益体现在 **Pareto 前沿外移**，而不是单点 pass@1。
4. `T=3` 的边际收益明显小于 `T=2`。

## 6. 五周计划与分工

三人：**A 环境与数据**，**B 训练与框架**，**C 评测与分析**（报告三人共写）。

| 周 | A | B | C | Gate |
|---|---|---|---|---|
| W1 | 数据清洗、难度校准、时间切分；沙箱 + 逐 assert judge | TRL 环境搭好；1.5B 单轮 GRPO 冒烟 | 评测脚本 + B0 基线；实验记录规范 | **G1**：1.5B 上 reward 曲线能涨 |
| W2 | 反馈格式打磨；失败用例抽取 | 7B 单轮 GRPO 正式训练；SFT 基线 | B0/B1/B2 对照表 | **G2**：7B pass@1 相对 base ≥ +5pt |
| W3 | 两轮环境（turn-2 模板 + 反馈注入） | 两轮 rollout 打通；GRPO-2turn | 修复增益分析（pass@1→2） | **G3**：修复轮 ≥ +3pt |
| W4 | 边界用例与作弊抽检 | 三奖励 + GDPO；权重扫描 | GDPO vs GRPO 对照 + Pareto 图 | **G4**：出主结果表 |
| W5 | 一键复现脚本；单测 | adapter 与训练日志整理 | 报告、图表、答辩 | 交付 |
| W6 | 缓冲 | 缓冲 | （可选）T=3 扩展 | 答辩 |

**Gate 规则**：任一 gate 未过，**不进入下一阶段**，先定位原因。G2 是最关键的一道——7B 单轮都涨不动，说明奖励或数据有问题，加 GDPO 只会放大噪声。

**降级预案**：G2 到 W2 末仍未过，切回[附录 A](#附录-a编排层-rl方案v1保留作对照)的编排层 Q-learning（确定能出结果），训练线作为"探索性实验"写入报告。

## 7. 风险与预案

| 风险 | 概率 | 影响 | 预案 |
|---|---|---|---|
| 组内奖励全 0 / 全 1，无梯度 | 高 | 高 | 难度校准筛题；训练中动态过滤退化组 |
| 7B + vLLM 在 48GB 上 OOM | 中 | 高 | 降 group size / 序列长度；退 3B；vLLM sleep mode |
| TRL 的 `apply_gdpo` 未合入目标版本 | 中 | 中 | 用 [NVlabs 的 verl 实现](https://github.com/NVlabs/GDPO)；或自己实现（只改优势计算，几十行） |
| 多轮 rollout 在 TRL 里跑不通 | 中 | 高 | 切 verl；或把 turn-2 离线预生成成固定数据集（退化为离线 RL） |
| 奖励作弊（硬编码公开样例） | 中 | 高 | 隐藏集分布扰动；抽检 20 条；`R_eff` 惩罚投机 |
| SFT 基线打不过 | 中 | 中 | 调整 SFT 数据量；把结论写成"RL 在难例上更优"，仍是有效结果 |
| 时间不够 | 中 | 高 | G2 不过就降级；W4 末冻结实验 |

## 8. 验收标准

1. 一条命令复现主结果：`python -m rl_algo.eval --config configs/eval.yaml --ckpt <adapter>`，产出 `summary.md` + 3 张图（学习曲线、Pareto、修复增益）。
2. 100 题 held-out 上：GRPO-2turn 的 pass@1 比 base ≥ +5pt；GDPO 在 AC 不劣的前提下，平均轮数或 TLE 率更优。
3. 交付：LoRA adapter、训练脚本、清洗与难度校准脚本、SFT 基线、全部实验原始日志。
4. 报告含：相关工作对比、奖励设计与 GDPO 动机、四条基线对照、消融、失败分析、复现说明。

## 附录 A：编排层 RL 方案（v1，保留作对照）

**核心思想**：冻结模型，只学"下一步该向哪个工具要反馈"的策略，7 个动作（`submit / run_public / fuzz_small / fuzz_large / targeted_fix / rewrite / audit`），用表格 Q-learning 或 LinUCB 在预算 `T=8` 内决策。

**为什么保留**：

1. **降级预案**：训练线 G2 不过时，这套能在 1 周内出结果——环境、判定、反馈都已具备，只需加策略层。
2. **对照基线**：报告的"固定 workflow vs 学习型编排"可以作为一节，说明"同样的工具，把学习放在哪一层收益更大"。
3. **数据生成器**：编排层采出的轨迹可以作为 SFT 或离线 RL 的冷启动数据。

**不做的部分**：不把它当主线。两套 RL 同时做就是分层 RL，五周做不完。
